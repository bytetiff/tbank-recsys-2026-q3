# Протокол: сильный ручной бейзлайн против автогенерации признаков

Зафиксирован 25 октября 2026 года, до просмотра каких-либо метрик качества моделей. Прежние `src/`, `configs/`, `runs/` и `reports/` не меняются. Код прежнего пайплайна только импортируется для варианта old_manual.

## Данные

- Yambda-50M, та же когорта: 1000 пользователей (`cohort_seed=1729`) со всей историей, 5 040 719 событий. Берётся подготовленный файл прежнего пайплайна. К нему по `row_id` присоединяются `played_ratio_pct`, `is_organic` и `track_length_seconds` из исходного `multi_event.parquet`. Совпадение пользователя, трека, времени и типа события проверяется для каждой строки.
- Исполнитель и альбом берутся из `artist_item_mapping.parquet` и `album_item_mapping.parquet` (Hugging Face `yandex/yambda`). Это статические свойства трека; если их несколько, берётся минимальный id. Если метаданных нет, трек получает собственный псевдо-id.
- Цель: `listen` с `played_ratio_pct > 50` в следующие 7 дней после cutoff, как в прежнем пайплайне.

## Разбиение

Шесть недельных cutoff, заканчивающихся на `end_exclusive=26000005`: train0–train2, dev, selection, test. Это те же cutoff, что у прежнего пайплайна. Признаки и кандидаты строятся только из событий с `timestamp < cutoff`. Метки берутся только из `[cutoff, cutoff + 7 дней)`.

Роли:
- train0–2 используются для обучения;
- dev нужен для early stopping (Logloss) и для обучения скрининговой модели;
- selection — для выбора K автоматического набора;
- test открывается один раз, на стадии `final`.

## Кандидаты (общие для всех моделей)

Из каждого источника берутся до 400 / 100 / 50 / 100 треков:
- `history`: треки, которые пользователь чаще всего дослушивал за 90 дней;
- `recent`: последние прослушанные различные треки;
- `artist`: ещё не слышанные треки топ-10 исполнителей пользователя;
- `popular`: популярные в когорте за 7 дней.

Флаги источников доступны всем бустингам, кроме old_manual: он воспроизводит прежний набор.

## Варианты

| Вариант | Признаки |
| --- | --- |
| popular | популярность за 7 дней, без обучения |
| history_count | число дослушиваний пары за 90 дней, без обучения |
| old_manual | прежние 36 агрегатов (окна 7, 30 дней и вся история) и категориальные user_id, item_id |
| manual | 48 спецификаций грамматики, выбранных вручную, 7 дополнительных признаков и 4 флага источника |
| auto | K признаков, отобранных автоматически из полной грамматики (около 1000 спецификаций), и 4 флага источника |
| auto_manual | manual вместе с теми признаками auto, которых нет в manual |

Грамматика строится как ключ × фильтр × окно × агрегация:
- ключ: user, item, artist, album, user×item, user×artist, user×album;
- фильтр: all, listen, full >50%, skip <20%, like, dislike, organic;
- окно: 1, 3, 7, 14, 30, 90 дней и вся история;
- агрегация: count, recency, mean played_ratio, число различных треков, доли full/skip/like от прослушиваний, доля пары в дослушиваниях пользователя.

## Автоматический отбор

1. Скрининг. Берётся случайная подвыборка из 300 пользователей (seed 7). На ней строится вся грамматика по train0–2 и dev. Обучается CatBoost на 400 итераций с early stopping по dev. Признаки ранжируются по PredictionValuesChange. Признак с |corr| > 0.98 к более важному удаляется. Сохраняются первые 120 признаков.
2. Выбор K из {20, 40, 70, 120} по macro NDCG@10 на selection, на всех 1000 пользователях, с seed 17. При равенстве выбирается меньшее K.

## Обучение и оценка

Все бустинги обучаются одинаково: CatBoost CPU, depth 6, lr 0.08, l2 3, до 2000 итераций, early stopping 100 по Logloss на dev, обучение на train0–2. Гиперпараметры не подбираются ни для одного варианта, поэтому ни один вариант не получает преимущества от подбора. Финал: seeds 17, 29, 43.

Метрики:
- NDCG@10 (основная), Recall@10 и Recall@100 — от всех различных целей горизонта, включая пропущенные генератором;
- recall кандидатов;
- ROC-AUC и LogLoss по строкам кандидатов.

Пользователи без целей исключаются. Сравнение с manual: для каждого пользователя разности усредняются по seeds, затем paired bootstrap по пользователям (2000 повторов, seed 2718). Интервал разведочный и условный относительно когорты.

Стоимость: время и пиковый RSS каждой стадии, число признаков, время обучения и предсказания.

## Ограничения, известные заранее

Одна когорта из 1000 активных пользователей и один период. Популярность и агрегаты объектов считаются только по когорте. Интервалы не учитывают неопределённость выбора K и скрининга.

## Дополнение 1: подбор гиперпараметров на dev

Записано 25 октября 2026 года после первого финала, до запуска подбора. ТЗ требует подбирать гиперпараметры на валидации, а в первом финале у всех вариантов были общие фиксированные параметры. Поэтому добавлена стадия `tune`.

- Для каждого бустинга (old_manual, manual, auto, auto_manual) перебирается сетка depth {6, 8} × learning_rate {0.05, 0.1}.
- l2 = 3, до 2000 итераций, early stopping 100 по Logloss на dev, seed 17.
- Выбирается максимум NDCG@10 на dev. При равенстве берётся меньшая глубина, затем больший lr.
- Набор признаков не меняется: K=120 выбран раньше на selection.
- Затем `final --tuned` повторяет финал с выбранными параметрами (3 seeds) и пишет `final-tuned.json`.

Первый финал (`final.json`) сохраняется без изменений, в отчёте показаны оба. Правило подбора одинаково для всех вариантов и не зависит от результатов test. Test первого финала уже открыт, поэтому повторный финал — не независимая проверка, а устойчивость вывода к подбору гиперпараметров.
